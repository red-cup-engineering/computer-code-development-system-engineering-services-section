# JSNode Engine

`@red-cup-engineering/jsnode-engine` is the JSNode section's source-engine head. It has a deliberately ascending family: immutable source records and tokens; admitted syntax and module data; portable codemod plans; then explicit CLI effect boundaries that can inspect or write a receipt. It admits JavaScript, TypeScript, JSX, TSX, and JSON syntax; reads complete module request and export surfaces; and applies validated non-overlapping character edits without reprinting unrelated source.

This describes current code, not final ownership. Parsing and source-bound edit
planning remain code-engine capabilities. Code generation, codemod execution,
relocation work, and code missions are Agent Organization Engine work over
Sign carriers. This package supplies coding context and exact edit primitives
to those consumers. See the [AOE work contract](../../../agent-computer-system-engineering-services-section/apps/agent-organization-engine/content/text/documents/specifications/software-development-work.md).

It is a specialization of `typed-computer-system-engine`: its parse operation is an explicit host capability over typed source and syntax-tree data. The system engine composes the code and networking engines, which both use the computer data type engine.

## Competitive surface, measured 2026-09-10

Acorn, Espree, Babel Parser, and Meriyah all make parsing available; ESTree supplies the common tree vocabulary; jscodeshift runs a transform over files. JSNode meets the parser job for the house's JavaScript family, including TypeScript and TSX (which Meriyah explicitly excludes), and its module analysis works across ESM, dynamic import, and CommonJS.

Its structural advantage is the change carrier: `planJsnodeModuleSpecifierRewrite` only selects parser-admitted module literals, binds the plan to a SHA-256 source record, validates its non-overlapping spans, and yields an output-digest receipt. The Agent Organization Engine now owns the module-rewrite work command and its Sign evidence. This parser remains a lower-level code primitive. It is not yet a full Babel-proposal or Flow parser, nor a general arbitrary-visitor replacement for jscodeshift.

The shipped scripts include `jsnode-inspect` (`syntax`, `tokens`, `modules`, or `exports`). AOE owns `aoe-codemod` and `aoe-relocate` for software-change work.

## Inference-guided code missions

The AOE `@red-cup-engineering/animating/software-change/mission` owns bounded code-mission work. It obtains inference through the shared inference dispatch, applies declared changes in an isolated copy, verifies them, and emits a proposal without mutating a customer's territory. Invoke `aoe-code-mission` or import `executeSoftwareMission` from that AOE export. This code engine supplies the coding-context projection and sandboxed edit primitives that the mission uses.
